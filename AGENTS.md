# Правила разработки TaskOS

Эти правила постоянные. Их не обходят «на один коммит» и не отключают ради скорости.

## Ветки и git

- В `main` и `master` не коммитить, не мержить и не переключаться ради правки.
- Разработка TaskOS идёт в `dev/taskos-mvp` или в новой ветке от неё. Существующую ветку не удалять и не переписывать.
- Запрещены `git push --force`, `git reset --hard`, `git clean`, удаление `main`, rebase чужой истории и merge без явного подтверждения человека.
- Перед изменением репозитория смотреть `git status`. Грязное дерево не «чинить» автоматически.
- Для кодовой задачи пользователя ветка только вида `task/TASK-0001-short-name`.
- Коммит такой задачи не включает `.taskos/` и `.taskos-local/`.

## Секреты

- Не добавлять API-ключи, GitHub-токены, пароли, cookies и `.env`.
- Не логировать секреты в timeline, raw log и `runs/*.jsonl`.
- Если в индекс попал файл, похожий на секрет, коммит останавливается.

## Хранилище

- Исходный запрос пользователя — `request.md`. Его не перезаписывать и не «улучшать».
- Не ломать чтение уже записанных `task.json` и `PROJECT-*.json`. Новое поле допустимо только с безопасным значением по умолчанию в `normalize`. Смена смысла или формата требует миграции и нового `schemaVersion`.
- `.taskos-local/` остаётся в `.gitignore`.

## AI

- UI, оркестратор и домен не знают флагов конкретного CLI. Вызов модели живёт в реализации `AIProvider`.
- Сейчас единственная реализация — `GrokBuildProvider`. Не имитировать Codex, ChatGPT или GLM и не хардкодить их имена по коду.
- Не вызывать xAI/OpenAI HTTP API и не подставлять API-ключи. Только локальный `grok`.
- Флаги CLI брать из `--help` установленной версии, не из памяти.

## Жизненный цикл

- `DONE` нельзя поставить в обход `USER_QA` и явного подтверждения. Сначала `READY`, потом `DONE`.
- Процент прогресса считает домен по весам этапов. Модель не сообщает «готово на N%».
- Одну задачу не запускать двумя процессами. Lock обязателен.
- Опасное действие (merge, push, удаление ветки, смена `main`) не выполняется само. Нужно подтверждение человека, а в MVP этих действий нет вообще.

## Перед завершением правки

- `npm test`
- `npm run typecheck`
- По возможности `npm run lint` и `npm run build`
- Не писать, что проверка прошла, если она не запускалась.
